# Local room and IPTV update, 26 October 2026

The user approved the current localhost behavior after requesting a rollback. That latest instruction superseded the rollback: the older files were not restored. The accepted layout and functioning player remain the baseline.

## Room changes

- One Participants control with a notification-style online count.
- Shared playback stays separate from the camera call. Local video participates in the same active-player layout.
- Incoming public messages scroll beneath shared playback and briefly fade upward through the lower 35% of the call area. Private messages, history replay, blocked people and the sender's own messages do not enter these overlays. Reduced-motion preference is respected.
- Landscape header hides after 3.5 seconds of idle playback and returns on pointer/keyboard activity. It stays available for paused playback, dialogs and the participant rail.
- Both playback and call volume use transparent controls over the video. Call volume stays accessible in the bottom controls when no video is selected.
- Short landscape screens use overlay bubbles for extra participants while the side rail is open, preserving height for the two main tiles.

## IPTV and saved videos

- Country defaults to the caller's IP country, using [Country.is](https://country.is/). Only country code and expiry are cached; IP address is not stored. A manual country choice takes precedence and survives reload. If lookup fails, worldwide general channels remain available. A VPN can change the detected country.
- Home and room share cached country/channel directories instead of fetching independently. Radio uses the same bounded cache. Country/language metadata is cached for a day and playlists for 15 minutes, with at most 16 cache entries.
- Movies, Saved and language filters join the existing categories. Language filtering intersects the country playlist with the selected [IPTV-org language playlist](https://github.com/iptv-org/iptv). No language is inferred from a channel's name.
- Initial room rendering is limited to 24 cards with Show more. Search debounces for 120 ms. Logos load lazily, and selection no longer rebuilds the home list.
- Green means playlist/media responded or playback was verified on this device. Yellow means unchecked, blocked, restricted or temporarily unavailable. Red requires a visible 404/410 response or repeated server failures. This is device-local evidence, not a worldwide uptime guarantee or a way around regional restrictions.
- Checks run only for visible room cards or the first few home search results, at concurrency two, with timeouts, bounded reads and cached results. A successful live player takes precedence over a late failed probe.
- The heart saves supported channels and video links on this device, and the Saved tab can reopen or remove them. It also preserves the existing room reaction. Temporary uploaded/device-local files are not falsely presented as permanent saved links. No account migration was made; saved items do not yet sync across devices.
